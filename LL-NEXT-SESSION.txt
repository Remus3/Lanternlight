=== OPS-72 WAS FILED AND CLOSED IN THE SAME SESSION ===

A store-drift guard failed intermittently. It was filed rather than dismissed,
then it FAILED AGAIN during the wrap's own final run - and that second failure,
in isolation on a loaded machine, is what made it fixable.

  THE MECHANISM. The test asserts that two stashes from an unchanged index leave
  THREE commits, because the second stash's `index on ` commit has the same tree,
  parent and subject as the first and so hashes to the same object. Incomplete: a
  commit object ALSO embeds author and committer timestamps at WHOLE-SECOND
  resolution. The collision happens only when both stashes are written inside the
  same second. Under load they straddled a boundary, git wrote two distinct
  objects, and the count came out 4. The two `index on master` entries in the
  failure report carried DIFFERENT SHAs, which is what settles it - a dedup
  failure and a miscount look identical in the number alone.

  FIXED BY CONSTRUCTION. GIT_AUTHOR_DATE and GIT_COMMITTER_DATE are pinned for
  the commands whose object identity the test depends on. No retry, no sleep, no
  widened assertion. Proved both ways with a deliberately forced 2 second gap:
  pinned it passes, unpinned it fails.

  THE DOCSTRING WAS THE REAL BUG and is corrected - it listed tree, parent and
  subject and omitted the timestamps, which is why the test was written in a way
  that could race at all.
