THE FIVE FINDINGS WORTH CARRYING, all measured here
  1. A SAFE LIST IS WHERE THE HOLES ARE. An adversarial pass defeated a guard
     this session shipped, twice, and fixing the second exposed a third - all
     three were entries on the guard's own SAFE list, admitted because the
     reasoning sounded right. Every POSITIVE specimen had been measured and no
     NEGATIVE one had. That asymmetry is where all three defects lived. If you
     keep a denylist, an allowlist or a KNOWN_GOOD set - and this repo keeps
     several - the question is not whether the entries are plausible, it is
     which of them was ever measured.
  2. `assert "NAME" not in os.environ` RENDERS THE WHOLE ENVIRONMENT into a
     pytest failure diff. You do not have to write the mapping as an operand;
     a membership test naming one variable is enough. `os.environ.keys()` is
     WORSE - KeysView reprs as KeysView(environ({...})), keys and values both.
     `os.environ.get(...)` renders only the retrieved value. The render COUNT
     is environment-specific - this machine gave three, an independent pass in
     a scrubbed environment gave two - so quote the mechanism, not the number.
  3. A COUNT FROM A SHARED DIRECTORY CARRIES THE TIMESTAMP OF THE READ. A
     relayed figure of 192,202 files measured 266,336 here hours later, with
     two of this session's own suite runs inside the difference. Same lesson as
     the vote tallies, in a different costume.
  4. A DIRECTORY'S DATE IS NOT ITS CONTENTS' DATE. A temp base was reported as
     "accumulating since 2026-04-22"; nothing in it was older than 29 hours.
     That one correction moved the whole fix: it is churn, not accumulation, so
     no cutoff expressed in DAYS can catch it and the producing suite is the
     only place it is fixable. pytest.ini now pins retention and the shared base
     fell from 266,336 files to 64,528.
  5. A CONFIG ASSERTION THAT READS THE CONFIG FILE IS TESTING YOUR TEXT EDITOR.
     An ini key the tool does not honour sits in the file looking correct while
     changing nothing, and --strict-config only catches keys pytest knows to be
     unknown. Ask the LIVE pytestconfig. See tests/test_tmp_retention.py.
